# Performance budget

Runnable form of `docs/03-architecture/17-performance-and-capacity.md`. A budget miss becomes a
task; budgets are never silently relaxed.

## API budgets (p95, server time)

| Endpoint group | Budget | Measurement |
|---|---|---|
| `GET /healthz`, `/readyz` | ≤ 50 ms | perf test |
| `GET /meta/*` | ≤ 150 ms | perf test |
| `GET /reports` (browse, filtered) | ≤ 250 ms | perf test |
| `POST /search` (text) | ≤ 300 ms | perf test |
| `POST /search` (image, cached embedding) | ≤ 800 ms | perf test |
| `GET /reports/{id}` | ≤ 200 ms | perf test |
| `POST /reports`, `POST /claims` | ≤ 500 ms | perf test |
| `GET /claims/{id}` (with messages page) | ≤ 250 ms | perf test |
| Admin lists | ≤ 300 ms | perf test |
| Any endpoint, p99 | ≤ 2× p95 budget | logs |

## Frontend budgets

| Metric | Budget | Tool |
|---|---|---|
| LCP (mobile 4G, `/`, `/reports/[id]`) | ≤ 2.5 s | Lighthouse CI |
| CLS | ≤ 0.1 | Lighthouse CI |
| INP | ≤ 200 ms | Lighthouse CI |
| JS per route (gzip) | ≤ 250 kB | build output check |
| CSS (gzip) | ≤ 50 kB | build output check |
| Images in lists | thumbnails only (480 px) | code review |

## ML budgets (CPU)

| Operation | p95 | Notes |
|---|---|---|
| `analyze-image` | ≤ 3 s | 1024 px input |
| `embed-text` (≤20 texts) | ≤ 400 ms | batched |
| `extract-attributes` | ≤ 50 ms | lexicon |
| Match scoring per pair | ≤ 50 ms | worker |
| Worker `report.process` end-to-end | ≤ 30 s | includes ML calls |

## Database budgets

| Query class | Budget |
|---|---|
| Point reads | ≤ 20 ms |
| Browse query | ≤ 100 ms |
| FTS query | ≤ 150 ms |
| ANN query (top 50) | ≤ 80 ms |
| Migration on empty DB | ≤ 30 s |

## Enforcement

| When | What |
|---|---|
| Every PR | bundle size check; new query `EXPLAIN` review |
| `gate:full` | optional perf job (flagged) |
| M8 | Lighthouse CI + API perf tests + k6 load check |
| Monthly | review `pg_stat_statements` slow queries |

## Test data for perf

- 2,000 reports, 5,000 users, 10,000 images (metadata), 1,000 matches.
- Generated by `scripts/seed-perf.mjs` (not committed as data; regenerated per run).
- ML stubbed for API perf tests; real ML measured separately on the ML service.

## Reporting

Results are recorded in `docs/06-quality/08-accessibility-audit.md`-style dated files
(`perf-report-<date>.md` when the M8 run happens) and summarised in `status.md`.
