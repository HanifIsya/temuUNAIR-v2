# BLK-004 — Auth.js `pages` + magic-link missing despite BE-002 DONE

## Question

`TMU-BE-002` is `DONE` with the AC "Magic link active only when `NODE_ENV=development`
and still domain-checked" ticked, yet:

1. `apps/web/src/server/auth/config.ts` configures **only** the Google provider — no
   Email/magic-link provider exists anywhere in `apps/web/src` (grep: no `EmailProvider`,
   `Nodemailer`; "magic" appears only in rate-limit comments), and there is no dev
   magic-link route;
2. the config declares **no `pages`** (`pages: { signIn, error }`), so Auth.js redirects
   OAuth failures — including the domain rejection from the `signIn` callback — to its
   own default error surface instead of the custom `/auth/error` page built in
   TMU-FE-001.

Impact: SCR-002 ("Never show a raw provider error") is violated in production for every
domain rejection; SCR-002 region 3 (dev magic-link form) has no server side; E2E-01
cannot verify the failure path. `apps/web/src/server/**` is be-lane — the fe lane (which
found this during FE-001 DoR research) may not touch it.

## Evidence

- `buildAuthOptions()` in `apps/web/src/server/auth/config.ts`: `providers: [Google(...)]`,
  callbacks `signIn` (domain allowlist → `false`), `session`; no `pages`, no Email
  provider (full file reviewed 2026-10-05).
- `grep 'magic|Nodemailer|EmailProvider|pages\s*:'` over `apps/web/src` → only
  rate-limit.ts comments and magic-byte upload tests.
- `docs/08-project/tasks/TMU-BE-002.md`: status DONE, AC "Magic link active only when
  `NODE_ENV=development`" marked `[x]`.
- SCR-002: "Never show a raw provider error"; region 3 "Dev-only magic-link form
  (`NODE_ENV=development` only)".

## Options

1. **Reopen/extend TMU-BE-002** (owner be-dev): add `pages: { signIn: "/login",
   error: "/auth/error" }` to `buildAuthOptions` + tests, and either implement the dev
   magic-link provider or strike the AC with a DEC entry (a real Email provider needs
   SMTP secrets — `AUTH_EMAIL_*` is absent from `.env.example`).
2. **File a follow-up `TMU-BE-*`** for the same scope and annotate BE-002's AC as
   `moved → BLK-004`.

Decision belongs to a human/the BE owner. FE-001 shipped around it: `/auth/error` reads
`?error=` codes (works once be wires `pages.error`), and the dev magic-link form was
deferred out of FE-001 with this file as the reference.
