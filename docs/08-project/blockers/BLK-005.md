# BLK-005 — TMU-FE-002 references a nonexistent `FR-AUTH-006`

## Question

`TMU-FE-002` (app shell) lists `refs: [FE-01, IA, SCR-003, FR-AUTH-006]`, but
**`FR-AUTH-006` does not exist**: `docs/01-product/05-functional-requirements.md` ends at
`FR-AUTH-005` (account deletion), and a repo-wide grep finds `FR-AUTH-006` only in the
task file itself. DoR check #3 ("Linked FR/US/SCR/API/DB IDs exist in merged docs") fails,
so the task is marked `BLOCKED` and must not start "optimistically".

The goal sentence — "locale switcher (`id` default, `en`) persisting via `PATCH /me`" —
mirrors **`FR-I18N-001`** ("serve UI in Bahasa Indonesia by default and English as an
option, persisting the choice per user" → `API-ME-02`) almost verbatim, together with
**`FR-AUTH-004`** (update display name and locale). But correcting a task's refs is a
spec-ownership decision: was `FR-AUTH-006` a typo, or was a distinct requirement meant to
be authored and never written?

## Evidence

- `docs/01-product/05-functional-requirements.md:20..24` — FR-AUTH-001..005 only; no 006.
- grep `FR-AUTH-006` across `docs/` → only `docs/08-project/tasks/TMU-FE-002.md:11`.
- The **behaviour** itself is specified, only the FR pointer dangles:
  - `docs/02-design/04-information-architecture.md` — bottom nav 5 items (Beranda `/home`,
    Cari `/reports`, Lapor center chooser, Klaim `/claims`, Akun `/me/settings`), admin
    sidebar under `/admin`, "Locale is a user preference … + `LocaleSwitcher`";
  - `SCR-003` — CMP-001 app shell, CMP-002 `NotificationBell`, `API-NTF-004` unread;
  - `FE-01` route group `(app)`, `FE-03` CMP-001/002.
- Secondary thin spot (DoR #5): `docs/01-product/07-acceptance-criteria.md` has no Gherkin
  section for `FR-I18N-001`/`FR-AUTH-004` (locale round-trip), unlike most covered FRs.

## Options

1. **Correct the refs** to `[FE-01, IA, SCR-003, FR-I18N-001, FR-AUTH-004]` (and optionally
   add a Gherkin block for the locale round-trip to `07-acceptance-criteria.md`) — a
   one-line `_common` fix that unblocks FE-002 immediately. **Recommended**: the intended
   requirement is unambiguous from the goal text.
2. **Author `FR-AUTH-006`** as a real requirement first (docs lane: FR table row,
   traceability, AC block), if a distinct new FR was intended — then unblock.
3. Leave FE-002 `BLOCKED` and run `TMU-OPS-034`, `TMU-QA-001` or `TMU-META-008` meanwhile.

## Impact while open

The entire remaining FE lane stalls: `TMU-FE-003` and `TMU-FE-005` depend on
`TMU-FE-002`, and `TMU-FE-004`/`TMU-FE-006` chain behind those. Only `TMU-OPS-034`
(compose bring-up), `TMU-QA-001` (contract runner) and `TMU-META-008` (doc governance)
remain runnable without a decision.

## Resolution

2026-10-05 — **option 1** chosen by the human: refs corrected to
`[FE-01, IA, SCR-003, FR-I18N-001, FR-AUTH-004]`, `TMU-FE-002` back to `TODO`, blocker
closed. The optional Gherkin addition for `FR-I18N-001` lives in docs-lane files
(`01-product/07-acceptance-criteria.md`) and is tracked as a follow-up note in the task
file rather than edited cross-lane.
