# BLK-006 — CI `build`/`e2e` blocked by a be-lane route-path defect

## Question

PR #46 (TMU-FE-003) is the **first pull request this repository has ever run CI on for
application code** (previous tasks were merged locally per environment rules, so the
`build` and `e2e` jobs never executed against the app). Both required jobs fail with
`Module not found: Can't resolve '../../../../server/handlers/meta'` (and the
`uploads/[id]/complete` equivalent) — five API route files import their handlers one
`../` too few:

| File (at `apps/web/src/app/api/`) | Import as written | Resolves to | Needs |
|---|---|---|---|
| `v1/meta/campuses/route.ts` | `../../../../server/handlers/meta` | `src/app/server/…` ✗ | 5×`../` |
| `v1/meta/categories/route.ts` | `../../../../server/handlers/meta` | `src/app/server/…` ✗ | 5×`../` |
| `v1/meta/drop-points/route.ts` | `../../../../server/handlers/meta` | `src/app/server/…` ✗ | 5×`../` |
| `v1/meta/locations/route.ts` | `../../../../server/handlers/meta` | `src/app/server/…` ✗ | 5×`../` |
| `v1/uploads/[id]/complete/route.ts` | `../../../../../server/handlers/uploads` | `src/app/server/…` ✗ | 6×`../` |

The other 6 API routes resolve correctly. Root cause of the blind spot: the gate's
`typecheck` runs `tsc -p tsconfig.json` (root config includes only `scripts/**`) plus
`tsc -p tsconfig.test.json` (covers test-imported sources — API routes are not imported
by any test), and `scripts/gate.sh` has no `build` step, so webpack/Next is the first
tool to resolve these paths.

`apps/web/src/app/api/**` is **be-lane** (`.agent/lanes.json`), so the fe lane may not
touch these files — lane check would fail and no green gate would be possible.

## Evidence

- `gh run view --job=111588123069 --log-failed` (e2e): five `Module not found` errors,
  all listed above; `build` job fails the same way via `@temuunair/web#build`.
- Repository scan (`scan-routes.js`): `broken: 5, ok: 6` — exactly the five files.
- Introduced by `405d74c` (BE-005) and `ff10b2e` (BE-004); never executed by any CI.
- `git ls-tree origin/main apps/web/src/app/api/` is empty — the routes exist only on
  agent branches, which is why no prior run surfaced this.

## Decision (human, 2026-10-05)

**Lane exception authorized** (option: "Authorize lane exception"): the fe lane is
temporarily widened in `.agent/lanes.json` (itself a `_common` file any lane may edit)
to include exactly these five `route.ts` paths; the off-by-one imports are corrected in
the TMU-FE-003 review-fix push; this BLK documents the authorization. Mirrors the
BLK-003 option-2 precedent (`41e3982`, "grant be lane access to `tests/contract/**`").

## Second authorization (human, 2026-10-05, same session)

After the five import fixes landed, CI `build`/`e2e` progressed past module resolution to
Next's typecheck and failed on a **pre-existing** defect in a sixth be-lane file,
`apps/web/src/app/api/auth/[...nextauth]/route.ts:46`: it called `handler(request)`, but
`next-auth@5.0.0-beta.29`'s `NextAuth()` returns a plain object
(`{ handlers: { GET, POST }, auth, signIn, ... }` — `index.js` `return { handlers: ... }`),
so `NextAuthResult` has no call signature: a type error under `next build` **and** a
runtime `TypeError` on every `/api/auth/*` request. It was masked until now because
`origin/main` does not contain the BE-stack file at all
(`git ls-tree origin/main apps/web/src/app/api/` is empty — see Evidence), and because the
module-not-found failure aborted the build before typecheck ran. No test references the
route (glob + grep: zero matches).

**Question asked** ("Be-lane auth fix") → answer: **"Authorize this one-file fix"**.
Fix applied: destructure `{ handlers }`, dispatch
`request.method === "POST" ? handlers.POST(request) : handlers.GET(request)`, wrapper
parameter typed `NextRequest` (handlers take `(req: NextRequest)`); verified by local
`pnpm build` (red before, green after) plus the full gate.

## Resolution

1. `.agent/lanes.json` → `fe` gains the five explicit `route.ts` paths (scoped, not
   `app/api/**` wholesale).
2. One `../` added per import; `pnpm build`/e2e re-run to green.
3. Follow-up for ops/meta (non-blocking): decide whether the five paths stay in the fe
   lane permanently or re-home under `be` with a permanent depth-corrected fix owner.
